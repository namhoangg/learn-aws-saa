> [!COST]
> Athena SQL queries on S3 are billed at **USD 5 per TB scanned** (us-east-1), with a 10 MB minimum per query. This lab runs about 20 queries and scans a few hundred megabytes in total, which costs a fraction of a cent, and stores about 100 MB in S3 (also a fraction of a cent per day). Nothing in this lab runs by the hour, so a forgotten resource only keeps costing S3 storage. Still do the **Cleanup** section when you are finished, unless you continue to lab 02 or lab 03, which reuse the bucket, database and tables.

You will build the classic "cheap and fast Athena" story with real numbers: about 45 MB of raw CSV orders split into three monthly partitions, a workgroup with a guardrail, then the same report run four ways. Each run shows the **Data scanned** figure that Athena bills on, so you can see the savings instead of taking them on trust.

## Prerequisites

- An AWS account and an IAM identity with permissions for Athena, AWS Glue Data Catalog and S3 (for example the `AmazonAthenaFullAccess` and `AmazonS3FullAccess` managed policies, or `AdministratorAccess` in a personal lab account).
- A Region where Athena is available. The steps use `us-east-1`; if you also plan to do lab 03, pick a Region that supports 4-RPU Redshift Serverless (for example `us-east-1`, `us-east-2`, `us-west-2` or `eu-west-1`).
- **AWS CloudShell** (open it from the CloudShell icon in the console toolbar). It already has the AWS CLI v2 and Python 3 configured for your identity and Region. Keep the same CloudShell tab open for the whole lab because later commands reuse shell variables.

## Steps

### Step 1: Create a bucket and generate the sample data

Both the console and CLI paths start here, because the data is generated by a small Python script in CloudShell. The script writes 100,000 synthetic orders per month into Hive-style folders (`year=2026/month=07/`), which is the layout Athena, Glue and Redshift Spectrum understand as partitions.

In CloudShell, save the script:

```bash
cat > make_sales.py <<'EOF'
"""Write one CSV file of synthetic orders per month, in Hive-style folders."""
import calendar, csv, os, random, sys

year, months = sys.argv[1], sys.argv[2:]
countries = ["US", "DE", "FR", "GB", "JP", "IN", "BR", "AU", "CA", "VN"]
channels = ["web", "mobile", "store"]
catalog = {
    "electronics": [("headphones", 79.0), ("smartwatch", 199.0), ("charger", 25.0), ("speaker", 120.0)],
    "home": [("lamp", 35.0), ("kettle", 45.0), ("blender", 89.0), ("rug", 150.0)],
    "sports": [("yoga-mat", 30.0), ("dumbbell", 55.0), ("bike-helmet", 70.0), ("running-shoes", 110.0)],
    "books": [("novel", 15.0), ("cookbook", 28.0), ("travel-guide", 22.0), ("comic", 12.0)],
}
payments = ["card", "paypal", "wallet", "cash"]
words = ("fast delivery gift wrap please leave at door customer asked about warranty "
         "repeat buyer promo code applied fragile item call before weekend order loyalty member").split()

for m in months:
    random.seed(int(year) * 100 + int(m))
    days = calendar.monthrange(int(year), int(m))[1]
    folder = f"sales/year={year}/month={m}"
    os.makedirs(folder, exist_ok=True)
    with open(f"{folder}/sales-{year}-{m}.csv", "w", newline="") as f:
        out = csv.writer(f, lineterminator="\n")
        out.writerow(["order_id", "order_date", "customer_id", "country", "channel", "product",
                      "category", "quantity", "unit_price", "discount", "payment_method", "notes"])
        for i in range(1, 100001):
            category = random.choice(list(catalog))
            product, price = random.choice(catalog[category])
            out.writerow([
                f"O{year}{m}{i:06d}", f"{year}-{m}-{random.randint(1, days):02d}",
                f"C{random.randint(1, 20000):05d}", random.choice(countries),
                random.choice(channels), product, category, random.randint(1, 5), price,
                random.choice([0.0, 0.0, 0.0, 0.05, 0.10, 0.15]), random.choice(payments),
                " ".join(random.choices(words, k=12)),
            ])
    print("wrote", folder)
EOF
```

Then create the bucket, generate three months and upload them:

```bash
REGION=${AWS_REGION:-$(aws configure get region)}
ACCOUNT=$(aws sts get-caller-identity --query Account --output text)
BUCKET=datalab-$ACCOUNT-$REGION
echo "Bucket: $BUCKET"

aws s3 mb "s3://$BUCKET" --region "$REGION"
python3 make_sales.py 2026 07 08 09
head -3 sales/year=2026/month=07/sales-2026-07.csv
aws s3 cp sales/ "s3://$BUCKET/raw/sales/" --recursive
aws s3 ls "s3://$BUCKET/raw/sales/" --recursive --human-readable --summarize
```

> [!CHECK]
> The listing shows three objects, one under each `year=2026/month=NN/` prefix, about 14.5 MiB each and roughly 43 MiB in total. The `head` output shows a header row followed by comma-separated orders. Write down the bucket name; the console steps ask for it.

### Step 2: Create a workgroup with a data usage guardrail

A workgroup holds the query result location, enforces it for everyone who uses the workgroup, and can cancel any single query that scans more than a limit. You start with a generous 1 GB limit and tighten it in Step 8.

:::console
1. Open the **Athena** console. If the navigation pane is hidden, choose the menu icon on the left to expand it, then choose **Workgroups** → **Create workgroup**.
2. For **Workgroup name** enter `datalab-wg` and for **Description** enter `Data analytics lab`.
3. For **Choose the type of engine**, keep **Athena SQL**. Keep the default automatic option under **Update query engine** and **AWS Identity and Access Management (IAM)** for **Authentication**.
4. Under **Query result configuration**, choose **Customer managed** and set **Location of query result** to `s3://<your-bucket>/athena-results/`.
5. Select **Override client-side settings** so every query in this workgroup uses these settings, and keep **Publish query metrics to CloudWatch** selected.
6. Choose **Create workgroup**.
7. Choose `datalab-wg` in the workgroup list, open the **Execution controls** tab and choose **Edit controls**. Set **Data scanned limit** to `1` **Gigabytes GB** and choose **Save**.
:::

:::cli
```bash
aws athena create-work-group --name datalab-wg \
  --description "Data analytics lab" \
  --configuration "ResultConfiguration={OutputLocation=s3://$BUCKET/athena-results/},EnforceWorkGroupConfiguration=true,PublishCloudWatchMetricsEnabled=true,BytesScannedCutoffPerQuery=1073741824,EngineVersion={SelectedEngineVersion=AUTO}"

aws athena get-work-group --work-group datalab-wg \
  --query 'WorkGroup.Configuration.{Results:ResultConfiguration.OutputLocation,Enforced:EnforceWorkGroupConfiguration,LimitBytes:BytesScannedCutoffPerQuery}'
```
:::

> [!NOTE]
> Athena can also store results for you: a workgroup set to **Athena managed** query results needs no bucket and keeps results for 24 hours. This lab uses a customer-managed location so you can see the result files in S3, which is also the model most exam questions describe.

> [!CHECK]
> `datalab-wg` is listed as **Enabled**, its result location is your `athena-results/` prefix, and its per-query limit is 1 GB (`1073741824` bytes in the CLI output).

### Step 3: Create a database and a partitioned table

The table is only metadata in the AWS Glue Data Catalog: column names and types, the CSV format, and the S3 prefix to read. Nothing is copied.

:::console
1. In the navigation pane choose **Query editor**.
2. In the upper right, set **Workgroup** to `datalab-wg`. If a dialog shows the workgroup's settings, choose **Acknowledge**.
3. Make sure **Data source** is `AwsDataCatalog`. In the query pane, run (choose **Run** or press **Ctrl+Enter**):

   ```sql
   CREATE DATABASE datalab;
   ```

4. Choose the plus (**+**) sign to open a new query tab, paste the statement below (replace `<your-bucket>`), and choose **Run**:

   ```sql
   CREATE EXTERNAL TABLE datalab.sales_csv (
     order_id       string,
     order_date     date,
     customer_id    string,
     country        string,
     channel        string,
     product        string,
     category       string,
     quantity       int,
     unit_price     double,
     discount       double,
     payment_method string,
     notes          string
   )
   PARTITIONED BY (year string, month string)
   ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
   STORED AS TEXTFILE
   LOCATION 's3://<your-bucket>/raw/sales/'
   TBLPROPERTIES ('skip.header.line.count' = '1');
   ```

5. Run `SELECT * FROM datalab.sales_csv LIMIT 10;` and look at the result.
:::

:::cli
```bash
# Helper: run one statement in the lab workgroup, wait, then print state, bytes scanned and up to 15 rows.
athq() {
  local QID STATE
  QID=$(aws athena start-query-execution --work-group datalab-wg \
    --query-string "$1" --query QueryExecutionId --output text) || return
  while :; do
    STATE=$(aws athena get-query-execution --query-execution-id "$QID" \
      --query QueryExecution.Status.State --output text)
    case "$STATE" in SUCCEEDED|FAILED|CANCELLED) break ;; esac
    sleep 2
  done
  aws athena get-query-execution --query-execution-id "$QID" --output table \
    --query 'QueryExecution.{State:Status.State,BytesScanned:Statistics.DataScannedInBytes,Reason:Status.StateChangeReason}'
  if [ "$STATE" = SUCCEEDED ]; then
    aws athena get-query-results --query-execution-id "$QID" --max-items 15 \
      --query 'ResultSet.Rows[*].Data[*].VarCharValue' --output text
  fi
}

athq "CREATE DATABASE datalab"
athq "CREATE EXTERNAL TABLE datalab.sales_csv (
  order_id string, order_date date, customer_id string, country string,
  channel string, product string, category string, quantity int,
  unit_price double, discount double, payment_method string, notes string)
PARTITIONED BY (year string, month string)
ROW FORMAT DELIMITED FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION 's3://$BUCKET/raw/sales/'
TBLPROPERTIES ('skip.header.line.count' = '1')"
athq "SELECT * FROM datalab.sales_csv LIMIT 10"
```
:::

> [!CHECK]
> The database and table statements succeed, and `datalab` with table `sales_csv` appears under **Database** in the left panel. The `SELECT` returns **no rows** and scans 0 bytes: the table is partitioned, and Athena only reads partitions that are registered in the catalog. None are registered yet.

### Step 4: Register the partitions and run a first query

`MSCK REPAIR TABLE` walks the table's S3 prefix, finds folders named like `year=2026/month=07/`, and adds each one to the catalog as a partition.

:::console
1. In a new query tab, run:

   ```sql
   MSCK REPAIR TABLE datalab.sales_csv;
   ```

2. Then run each of these and read the results:

   ```sql
   SHOW PARTITIONS datalab.sales_csv;
   ```

   ```sql
   SELECT * FROM datalab.sales_csv LIMIT 10;
   ```
:::

:::cli
```bash
athq "MSCK REPAIR TABLE datalab.sales_csv"
athq "SHOW PARTITIONS datalab.sales_csv"
athq "SELECT order_id, order_date, category, quantity, unit_price, year, month FROM datalab.sales_csv LIMIT 10"
```
:::

> [!CHECK]
> `SHOW PARTITIONS` lists `year=2026/month=07`, `year=2026/month=08` and `year=2026/month=09`. The `SELECT` now returns rows, and `year` and `month` appear as ordinary columns even though they exist only in the folder names: these are the "virtual columns" that partitioning creates.

> [!TIP]
> `MSCK REPAIR TABLE` is fine for a first load. For tables that gain a partition every hour or day, use `ALTER TABLE ... ADD PARTITION`, a Glue crawler (lab 02) or **partition projection**, which computes partition locations from rules and needs no catalog updates at all.

### Step 5: Measure a full scan, then let partitions prune it

Run the same revenue report twice: once over every month, once for August only. After each run, note the **Data scanned** value shown with the results (next to **Run time**).

:::console
1. Run the report over all months:

   ```sql
   SELECT category,
          ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue
   FROM datalab.sales_csv
   GROUP BY category
   ORDER BY revenue DESC;
   ```

2. Run it again for one month by filtering on the partition columns:

   ```sql
   SELECT category,
          ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue
   FROM datalab.sales_csv
   WHERE year = '2026' AND month = '08'
   GROUP BY category
   ORDER BY revenue DESC;
   ```

3. Run it once more, filtering on the `order_date` column instead of the partition columns:

   ```sql
   SELECT category,
          ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue
   FROM datalab.sales_csv
   WHERE order_date BETWEEN DATE '2026-08-01' AND DATE '2026-08-31'
   GROUP BY category
   ORDER BY revenue DESC;
   ```
:::

:::cli
```bash
REPORT="SELECT category, ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue FROM datalab.sales_csv"
athq "$REPORT GROUP BY category ORDER BY revenue DESC"
athq "$REPORT WHERE year = '2026' AND month = '08' GROUP BY category ORDER BY revenue DESC"
athq "$REPORT WHERE order_date BETWEEN DATE '2026-08-01' AND DATE '2026-08-31' GROUP BY category ORDER BY revenue DESC"
```
:::

> [!CHECK]
> The full report scans roughly **45 MB**, all three files. The partition-filtered report scans about **15 MB**, one file, and returns roughly a third of the revenue. The `order_date` filter returns the same August numbers as the partition filter but scans the full ~45 MB again: Athena can skip folders only when the filter is on a **partition column**. That is why tables are partitioned by the columns most queries filter on.

### Step 6: Convert the data to Snappy-compressed Parquet with CTAS

`CREATE TABLE AS SELECT` (CTAS) runs a query and writes its result as a new table in the format you choose. Here it rewrites the CSV as Parquet, compressed with Snappy and still partitioned by year and month. Partition columns must come last in the `SELECT` list.

:::console
1. In a new query tab run (replace `<your-bucket>`):

   ```sql
   CREATE TABLE datalab.sales_parquet
   WITH (
     format = 'PARQUET',
     write_compression = 'SNAPPY',
     external_location = 's3://<your-bucket>/curated/sales_parquet/',
     partitioned_by = ARRAY['year', 'month']
   ) AS
   SELECT order_id, order_date, customer_id, country, channel, product, category,
          quantity, unit_price, discount, payment_method, notes, year, month
   FROM datalab.sales_csv;
   ```

2. Open the **S3** console in another tab, browse to `curated/sales_parquet/` in your bucket and open the `year=2026/` folder.
:::

:::cli
```bash
athq "CREATE TABLE datalab.sales_parquet
WITH (format = 'PARQUET', write_compression = 'SNAPPY',
      external_location = 's3://$BUCKET/curated/sales_parquet/',
      partitioned_by = ARRAY['year', 'month'])
AS SELECT order_id, order_date, customer_id, country, channel, product, category,
          quantity, unit_price, discount, payment_method, notes, year, month
FROM datalab.sales_csv"

aws s3 ls "s3://$BUCKET/curated/sales_parquet/" --recursive --human-readable --summarize
```
:::

> [!CHECK]
> The CTAS query scans the full CSV once (about 45 MB). S3 now holds `month=07`, `month=08` and `month=09` folders of Parquet files, and their total size is noticeably smaller than the CSV. CTAS also registered the new table **and its partitions** in the catalog, so no `MSCK REPAIR TABLE` is needed.

### Step 7: Run the report on Parquet and compare

:::console
1. Run the all-months report against the Parquet table:

   ```sql
   SELECT category,
          ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue
   FROM datalab.sales_parquet
   GROUP BY category
   ORDER BY revenue DESC;
   ```

2. Run the August-only version with `WHERE year = '2026' AND month = '08'` added before `GROUP BY`.
3. Open the **Recent queries** tab and compare the **Data scanned** column for your four report runs.
:::

:::cli
```bash
PREPORT="SELECT category, ROUND(SUM(quantity * unit_price * (1 - discount)), 2) AS revenue FROM datalab.sales_parquet"
athq "$PREPORT GROUP BY category ORDER BY revenue DESC"
athq "$PREPORT WHERE year = '2026' AND month = '08' GROUP BY category ORDER BY revenue DESC"
```
:::

> [!CHECK]
> The revenue figures match the CSV runs exactly, but the Parquet runs scan only a few megabytes or less, because Athena reads just the four columns the report uses (`category`, `quantity`, `unit_price`, `discount`) and skips the bulky `notes` and `order_id` columns. Fill in a table like this from your own numbers:
>
> | Run | Table | Filter | Data scanned (yours) |
> |---|---|---|---|
> | 1 | sales_csv | none | ~45 MB |
> | 2 | sales_csv | partition (`month = '08'`) | ~15 MB |
> | 3 | sales_parquet | none | a few MB or less |
> | 4 | sales_parquet | partition (`month = '08'`) | about a third of run 3 |

### Step 8: Let the per-query limit cancel an expensive query

Tighten the workgroup limit to the minimum Athena allows, 10 MB, and run a full CSV scan and a Parquet query again.

:::console
1. Choose **Workgroups** → `datalab-wg` → **Execution controls** tab → **Edit controls**. Set **Data scanned limit** to `10` **Megabytes MB** and choose **Save**.
2. Back in the **Query editor**, run the all-months report against `datalab.sales_csv` (the first query from Step 5).
3. Run the all-months report against `datalab.sales_parquet` (the first query from Step 7).
4. Set the **Data scanned limit** back to `1` **Gigabytes GB** if you continue to lab 02.
:::

:::cli
```bash
aws athena update-work-group --work-group datalab-wg \
  --configuration-updates BytesScannedCutoffPerQuery=10485760
athq "$REPORT GROUP BY category ORDER BY revenue DESC"
athq "$PREPORT GROUP BY category ORDER BY revenue DESC"

# Restore the 1 GB guardrail if you continue to lab 02.
aws athena update-work-group --work-group datalab-wg \
  --configuration-updates BytesScannedCutoffPerQuery=1073741824
```
:::

> [!CHECK]
> The CSV query should end with status **CANCELLED** and a reason saying the query exceeded the workgroup's bytes-scanned limit; you are billed only for what it read before it stopped. The Parquet query succeeds under the same 10 MB limit. This is the standard answer to "stop analysts from running runaway queries": per-query limits in a workgroup, plus workgroup-wide data usage alerts through CloudWatch and SNS.

## Cleanup

Skip this section if you continue to lab 02 or lab 03; they reuse the bucket, the `datalab` database and both tables, and their cleanup sections point back here. Otherwise delete in this order:

- [ ] **Tables `sales_parquet` and `sales_csv`, and database `datalab`**: in the Athena **Query editor** run `DROP DATABASE datalab CASCADE;`, which removes the database and every table in it from the Data Catalog (the S3 files stay until the next item). CLI: `athq "DROP DATABASE datalab CASCADE"`.
- [ ] **Workgroup `datalab-wg`** (this also deletes its query history, saved queries and per-query limit): **Workgroups** → select it → **Actions** → **Delete**, enter `datalab-wg` at the prompt and choose **Delete**. CLI: `aws athena delete-work-group --work-group datalab-wg --recursive-delete-option`.
- [ ] **S3 bucket `datalab-<account>-<region>`** with the raw CSV, the Parquet files and the Athena results: in the **S3** console select the bucket → **Empty** (type `permanently delete`) → then **Delete** (type the bucket name). CLI: `aws s3 rb "s3://$BUCKET" --force`.
- [ ] **CloudShell files**: `rm -rf ~/sales ~/make_sales.py` (keep them if you plan to do lab 02, which reuses the script).
- [ ] **Final check**: the Athena **Workgroups** page lists only `primary`, the Glue console's **Databases** page has no `datalab`, and the S3 console has no `datalab-...` bucket. The next day, **Billing and Cost Management** → **Bills** shows at most a few cents for Athena and S3.
